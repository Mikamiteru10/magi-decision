# MAGI P0 验证实验

> 本目录是网页上线前的验证实验，三版人格模板（v1 → v2 → v3）的报告见 [`reports/`](reports/)。网页使用的人格就是这里的 `personas.py` 中的 v3，由 `scripts/gen_personas.py` 生成到 `src/personas.js`。

目的：在写界面之前，确认 gemini-decision-1 仅靠不同的人格描述，能否让三台 MAGI 投出有意义的分歧票。

## 文件

| 文件 | 内容 |
| --- | --- |
| `cases.json` | 60 个测试案件：共识类 20、价值冲突类 20（每个另附 2 个改写）、原作场景类 20 |
| `personas.py` | 三台 MAGI 的人格描述与子项问题，中文、英文各一套 |
| `run_p0.py` | 实验脚本，只用 Python 标准库，不需要 pip 安装任何东西 |
| `.env.example` | API Key 配置模板 |

## 运行步骤

1. **准备 Key**：在 Google AI Studio 生成一把**开发专用**的 Key（以后线上再另生成一把）。把 `.env.example` 复制一份并改名为 `.env`，把里面的占位文字换成这把 Key。`.env` 只留在你自己电脑上，不要发给任何人；`.gitignore` 已经把它排除在 Git 之外。
2. **检查标注（可选，约 10 分钟）**：打开 `cases.json`，`expected` 是我预设的三台倾向，顺序为 [MELCHIOR, BALTHASAR, CASPER]，1 = 承认，0 = 否决，null = 不预设。你觉得不对的直接改数字。
3. **先试跑一次假数据**，确认环境没问题（不消耗配额）：
   ```
   python run_p0.py --mock
   ```
4. **先跑 3 个案件试一下真实 API**：
   ```
   python run_p0.py --lang zh --limit 3 --no-paraphrase
   ```
   如果报错，把终端里的整段错误发给 Claude。
5. **正式跑**（中文和英文各 100 次请求，共约 2–3 分钟，在免费层额度内）：
   ```
   python run_p0.py --lang both
   ```
6. **把 `results/report.md` 发给 Claude**，一起判断是否通过第 1 道门槛。

中途断了直接重跑同一条命令即可，已完成的请求会从缓存续上。改了人格描述想重新测，加 `--fresh`。只想用已有数据重新生成报告，加 `--report-only`。

## 模板版本

| 版本 | 语言 | 改动 |
| --- | --- | --- |
| v1 | 中文、英文 | 第一版，2026-11-14 的结果在 `report.md` |
| v2 | 中文 | MELCHIOR 改为按期望值判断；BALTHASAR 更明确地风险厌恶；CASPER 对日常小事果断表态；两个全局问题换了问法 |

| v3 | 中文 | 按 TV 版第 13 集与旧剧场版重写三重人格：CASPER 只听此刻的心（爱、欲望、自尊），BALTHASAR 守护并养育"孩子"；新增"特别议案"判定，用于一票否决制 |

现在默认使用 v3。只需运行：
```
python run_p0.py
```
共 117 次请求（65 个案件 + 52 个改写），结果写入 `results/report_v3.md`，开头有 v1 / v2 / v3 的对比表。旧版本的缓存和报告不会被覆盖；想重跑旧版本，加 `--template v1` 或 `--template v2`。

v3 同时改了测试案件：c02（散步）改为冲突类，新增 d01–d05 五个"欲望 vs 责任"案件，并把 e02、e07、e12、e13、e19 标为特别议案。

## 报告里的指标

| 指标 | 含义 | 建议通过线 |
| --- | --- | --- |
| 冲突类分歧率 | 价值冲突类案件中，三台没有全票一致的比例 | ≥ 40% |
| 共识类一致率 | 共识类案件中，三台全票且方向正确的比例 | ≥ 90% |
| 人格方向正确率 | 冲突类中，标注为承认的那台概率是否高于标注为否决的那台 | ≥ 70% |
| 最大相关系数 | 三台承认概率两两之间的 Pearson 相关，取最大值 | ≤ 0.80 |
| 改写翻转率 | 同一冲突案件换种说法后，最终结果变化的比例 | ≤ 15% |

每个指标都会给出 w = 1.0 / 0.6 / 0.3 三列。w = 1.0 只用投票概率，w 越小，子项评分（证据、安全、真心等）的占比越大。三列都在同一批请求上离线算出，不会额外消耗配额。

## 已知不确定处

- 请求和响应格式根据发布两天内的公开资料编写（问题类型 `noul` / `choice` / `score`，响应在 `answers` 下）。如果官方实际格式不同，第 4 步会报错，把错误发给 Claude 改一下即可。
- `results/` 里会保存完整的原始响应，方便之后复查。
